# spring-shopping-precourse
## 구현 전략
- 데이터 저장: DB를 회원, 상품, 위시리스트 3개의 테이블로 구현해 자바 객체와 매핑 후 각 테이블에서 회원 정보, 위시리스트 목록, 상품 정보 관리(위시리스트를 기준으로 회원, 상품 TABLE은 1:N)
  - 회원 TABLE: 컬럼 [회원ID], [이메일],[비밀번호] 
  - 상품 TABLE: 컬럼 [상품 ID], [이름], [가격], [이미지 url]
  - 위시리스트 TABLE: 컬럼 [WHISHID], [회원 id], [상품 ID] (wishID는 고유g번호로 행마다 +1 증가), 회원/멤버 id는 UniqueKey
- 계층 구조: Controller, Service, Repository
  - Controller : 클라이언트로부터 핵심 요청 받음(HTTP), 응답 처리(JSON)
  - Service : 비즈니스 로직 구현
  - Repository : DB와 소통
- 인증 토큰 방식: JWT 방식, 토큰은 사용자를 판별
  - 회원가입/로그인 시 토큰 발급(payload에 회원id, 만료시간 가짐) 
  - 클라이언트는 'Authorization: Bearer {token}' 헤더로 전달
  - 서버는 서명(payload의 회원 id)을 검증해 회원 식별
- 오류 응답 형식: 커스텀 예외 + @RestControllerAdvice
  - 형식 : {message : "오류 내용"}
  - throw -> @ReControllerAdvice가 받고 -> 상태코드,JSON 변환
  - 400 유효성 실패 / 401 인증실패 / 403 권한 없음 / 404 대상 없음 / 409 중복

## 기능 목록
### 상품
- 구현계획: /api/products를 통해 상품 생성 이때 생성 필요 정보로 [이름, 가격, 이미지url]가짐
- 상품 객체에 대해 조회, 추가 삭제 기능 구현
  - []조회: /api/products/{productId}를 이용해 찾고자 하는 상품과 ID가 일치할 시
  - []추가: /api/products를 통해 추가 이때 유효성 검사 및 예외처리를 거침
  - []삭제: /api/products/{productId}를 통해 상품 삭제
  - []수정: /api/products/{productId} 기존 상품 TABLE와 productid일치할시 해당 상품 정보 수정 가능
  - []조회: /api/products를 통해 상품 테이블의 모든 목록 조회 가능

### 상품 유효성 검사(상품 추가 수정의 경우) : 400 BAD Request
- []각 유효성 검사에 대해 사용자 함수로 예외 처리하여 오류 유형에 따른 오류 메시지 출력
  - []이름 길이가 공백 포함 0<이름<=15자 벗어날시 -> 오류 메시지 출력 
  - []상품 이름의 특수 문자 () [] + - & / _ 아닌 특수문자일시 -> 오류 메시지 출력
  - []PurgoMalum API 호출하여 비속어 여부 검사 -> 비속어 포함 시 -> 오류 메시지 출력
  - []존재하지 않는 상품에 대해 조회, 수정, 삭제 -> 오류메시지 : 404 Not Found
  - []상품 가격이 음수(가격 < 0) -> 오류 메시지
  - []한글, 숫자, 영문, 공백에 대해서는 허용(단 연속되는 공백은 불가)

### 회원
- []회원가입 : /api/members/register를 통해 회원가입(회원 테이블에 정보[이메일, 비밀번호] 저장) -> 회원 등록 후 토큰 받음
- []로그인: /api/members/login를 통해 로그인(로그인 정보가 회원 테이블의 정보[이메일, 비밀번호]와 일치) -> 로그인 후 토큰 받음

  - []이미 회원 TABLE에 등록된 정보로 회원 회원가입 시도 -> 409 중복
  - []회원 TABLE에 등록되지 않은 정보로 회원 로그인 시도 -> 401 Unauthorized

### 위시 리스트
- 인증된 사용자만 사용 가능(해당 기능은 토큰으로 판별)
- []추가 : /api/wishes로 상품 위시리스트에 등록(회원당 wishID하나만 부여)
  - []위시리스트 상품 추가의 위시리스트 TABLE에서 상품 ID,회원 ID가 이미 존재하는 상품 -> 오류메시지 송출 : 409 중복
  - []존재하지 않는 상품 추가(상품 TABLE에 존재하지 않는 상품 id) -> 404 대상없음

- []삭제 : /api/wishes/{wishId}로 WISHID로 행 먼저 판별 후 상품 삭제(삭제하고자 하는 상품ID와 위시리스트의 상품ID가 일치할 때)
  - []위시의 회원 == 토큰의 회원 을 판별후에 위시리스트 상품 삭제 -> 아닐시: 403 권한없음
  - [] 존재하지 않는 위시 삭제 : 404 대상 없음
- []조회 : /api/wishes로 위시리스트의 상품 목록 조회

# 상품 : 조회,추가,삭제 기능
- 이름, 가격, 이미지 url가짐
- 이미지는 파일이 아닌 URL 입력 방식
- 유효성 검사 및 예외처리(상품 추가 수정으로 부터 유효성 검사 후 적절한 오류 응답 반환)
  - 상품 이름은 공백 포함 최대 15자  
  - 상품아래 사용가능 특수 문자: () [] + - & / _ 외에는 불가
  - 비속어 포함 x (PurgoMalum API 호출하여 비속어 여부 검사)

# 회원 로그인 : 회원 가입, 로그인 통해 사용자 인증 기능 구현
- 회원은 이메일, 비밀번호로 가입
- 로그인 시 이메일, 비밀번호 검증 -> 일치시 인증 토큰 발급
- 토큰 생성 방식은 자유

# 위시리스트 : 인증 사용자 대상 위시리스트 기능 구현
- 위시 리스트에 등록된 상품 목록 조회
- 위시 리스트에 상품 추가, 삭제 가능

#회원 API
/api/members/register POST 회원 가입 새 회원을 등록하고 토큰을 받는다.
/api/members/login POST 로그인 회원을 인증하고 토큰을 받는다.

#상품 API
/api/products POST 상품 생성 새 상품을 등록한다.
/api/products/{productId} GET 상품 조회 특정 상품의 정보를 조회한다.
/api/products/{productId} PUT 상품 수정 기존 상품의 정보를 수정한다.
/api/products/{productId} DELETE 상품 삭제 특정 상품을 삭제한다.
/api/products GET 상품 목록 조회 모든 상품의 목록을 조회한다.

#위시리스트 API
/api/wishes POST 위시 리스트 상품 추가 회원의 위시 리스트에 상품을 추가한다.
/api/wishes/{wishId} DELETE 위시 리스트 상품 삭제 회원의 위시 리스트에서 상품을 삭제한다.
/api/wishes GET 위시 리스트 상품 조회 회원의 위시 리스트에 있는 상품을 조회한다.
