## 기능 목록

회원이 상품을 조회한다.

'상품에는 이름, 가격, 이미지 URL이 포함된다.'

- 상품
    - 이름
    - 가격은 원 단위 정수이며 0원 이상이어야 한다.
    - 이미지 URL
- 상품 이름은 공백을 포함하여 최대 15자까지 입력할 수 있다.
    - '(), [], +, -, &, /, _' 가 아니면 예외 발생.
    - 공백만 있어도 안됨.
- 등록/수정 시 이름에 비속어가 있으면 저장 불가.
- 상품을 등록하면 ID가 부여되며, 그 ID로 상품을 조회할 수 있다.
- 전체 상품 목록은 등록 순서대로 조회할 수 있다.
- 상품을 수정해도 ID와 등록 순서는 유지. 
- 이름 | 가격이 유효하지 않으면 기존 상품을 유지.
- 상품을 삭제. 없는 상품은 수정/삭제 불가.


'회원은 이메일과 비밀번호로 가입할 수 있다.'

- 회원은 이메일과 비밀번호를 고유하게 가진다. 
  - 이메일의 localPart 도 공백이면, 안되고 어떤 규칙이 있겠지만, 일단 무시한다. 
    - 원래는 객체 자체가 비밀번호를 그대로 가지고 있지는 않지만, 그 부분은 일단 무시하자.
      
    - 이메일
      - localPart 와 domain (tom@gmail.com)기
      - 회원들 고유한 단일의 이메일을 가진다고 가정한다.
    - 비밀번호
      - 10자 이상이어야 함.
      - 그 외의 특수문자 등등 생략.
      - 무언가, 비밀번호가 내부적으로 암호화된 상태로 되어 있고, 암/복호화하는 것이 있겠다. 
      - 일단 인터페이스로 하고 PlainPasswordHashing 으로 해보자.

'가입, 로그인'

- 가입
  - 가입 시, Member 객체 생성한다.
  - 편리성을 위한 Id 도 생성.
  - 이미 가입된 이메일로는 가입할 수 없다.
  - 원문 비밀번호는 10자 이상이어야 한다.
  - 비밀번호를 인코딩한 후 저장하고 등록된 회원을 반환한다.

- 로그인
  - 이메일로 회원을 찾고 입력한 비밀번호가 저장된 비밀번호와 일치하면 회원을 반환한다.
  - 가입하지 않은 이메일과 틀린 비밀번호는 같은 오류로 처리한다.

- 인증 토큰
  - 가입이나 로그인에 성공하면 해당 회원의 인증 토큰을 발급한다.
  - 토큰으로 회원 ID를 조회할 수 있다.
  - 토큰은 메모리에 저장하며 프로세스를 재시작하면 사라진다.

- 위시 리스트
  - 같은 상품 다시 담기 → 수량 +1.
  - 위시 리스트에 담을 때 재고 예약 없음.
  - 구매 확정 시 재고 확인/차감 한 번에. 부족하면 구매 불가. 구매 구현 시 적용.
