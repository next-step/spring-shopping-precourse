# spring-shopping-precourse

## 구현할 기능

- [ ] 상품을 등록하고, 목록과 개별 상품을 조회하고, 상품을 수정·삭제한다.
- [ ] 상품 등록·수정 요청을 검증하고, 잘못된 요청에는 JSON으로 오류를 응답한다.
- [ ] PurgoMalum API로 상품명에 비속어가 포함되어 있는지 검사한다.
- [ ] 이메일과 비밀번호로 회원을 등록하고 인증 토큰을 발급한다.
- [ ] 로그인 요청의 이메일과 비밀번호를 확인하고 인증 토큰을 발급한다.
- [ ] 인증된 회원이 자신의 위시 리스트를 조회하고 상품을 추가·삭제할 수 있게 한다.

## 아키텍처와 학습 목표

이 프로젝트는 클린 아키텍처를 처음 적용해 보는 실습이다. 의존성이 안쪽으로 향하도록 설계하고, 그 결과 유스케이스를 Spring, 데이터베이스, 외부 HTTP 서비스 없이 실행하고 테스트할 수 있는 이유를 이해하는 것이 목표다.

`POST /api/products`부터 구현한다. 상품 등록 유스케이스 쪽에서 상품 저장과 비속어 검사에 필요한 인터페이스를 정의한다. JPA 기반 저장소와 PurgoMalum HTTP 클라이언트는 해당 인터페이스를 구현하고, Spring MVC 컨트롤러는 유스케이스를 호출한다. 상품명의 길이와 허용 문자를 먼저 확인한 뒤 PurgoMalum을 호출한다. PurgoMalum 장애 시 응답은 해당 케이스를 구현하기 전에 논의한다.

회원 비밀번호는 해시로 저장하고, 회원 가입과 로그인에는 같은 토큰 발급 방식을 사용한다. 위시 리스트 조회와 변경은 토큰으로 식별한 회원의 항목에 한정한다. 저장 방식의 세부 사항, 토큰 형식과 만료 시간, 위시 리스트 중복 추가, 상품 삭제 시 위시 리스트 처리 정책은 각 기능을 설계할 때 논의한다.

## 기능 구현 순서

기능마다 다음 순서를 반복한다.

1. 기능의 동작과 성공·실패 시나리오를 정의한다.
2. 클린 아키텍처에서 기능의 경계와 의존성 방향을 정한다.
3. 기능에 필요한 도메인 객체와 각 객체의 책임, 객체 간 관계를 정한다.
4. JUnit과 AssertJ로 첫 번째 동작을 검증하는 테스트를 작성한다.
5. 테스트를 통과하도록 구현한다. 남은 시나리오도 테스트 작성과 구현을 반복하고, 기능 단위로 커밋한다.

애플리케이션과 테스트 코드는 학습자가 직접 작성한다. AI는 [AGENTS.md](AGENTS.md)에 따라 설계 논의, 개념 설명, 테스트 시나리오 검토, 코드 리뷰를 돕는다.

## AI 활용 기록

- Codex로 프리코스 가이드 두 개를 읽고, 기능 목록과 구현 전략 초안을 작성했다. 논의에서 정한 아키텍처와 기능 구현 순서도 문서에 정리했다. 이후 AI를 어떻게 활용했는지, 직접 수정한 코드와 배운 점은 작업하면서 기록한다.
