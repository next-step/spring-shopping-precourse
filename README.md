# spring-shopping-precourse

## 기능 목록

### 상품 - 검증
- [x] 이름은 빈 문자열이거나 공백으로만 이루어질 수 없다
- [x] 이름은 반드시 15자를 초과할 수 없습니다.
- [x] 이름에는 특수 문자(`(), [], +, -, &, /, _`)만 사용할 수 있다
- [ ] 이름에는 비속어가 포함될 수 없다 (PurgoMalum API 사용)
- [x] 가격은 0보다 크고 1,000,000 이하이어야 한다
- [x] 이미지 URL은 `https://` 혹은 `http://`로 시작해야 한다

### 상품 - API
- [x] 상품을 등록하면 생성된 id를 반환한다
- [x] 상품 하나를 조회한다
- [ ] 상품 목록을 id 내림차순으로 조회한다 (없으면 빈 목록)
- [ ] 상품을 수정한다 (등록과 같은 검증 적용)
- [ ] 상품을 삭제한다
- [ ] 존재하지 않는 상품을 조회/수정/삭제하면 404를 반환한다
- [ ] 검증에 실패하면 400과 오류 메시지를 JSON으로 반환한다

### 회원가입
- [ ] 이메일은 반드시 이메일 형식이어야 한다
- [ ] 이메일은 무조건 중복되면 안된다
- [ ] 비밀번호는 반드시 15자 이상 65자 이하이어야 한다
- [ ] 회원가입에 성공하면 인증 토큰을 응답한다

### 로그인
- [ ] 이메일이나 비밀번호를 존재하지 않는 걸 혹은 틀린 걸 입력하면 "이메일 혹은 비밀번호가 잘못되었습니다."라는 메시지를 보낸다
- [ ] 로그인에 성공하면 인증 토큰을 응답한다

### 위시리스트
- [ ] 인증 토큰 없이 요청하면 401(UNAUTHORIZED)
- [ ] 위조된 토큰으로 요청하면 401(UNAUTHORIZED)
- [ ] 만료된 토큰으로 요청하면 401(TOKEN_EXPIRED)
- [ ] 다른 회원의 위시 상품을 삭제하려고 요청하면 403
- [ ] 내 위시리스트에 상품을 추가한다
- [ ] 내 위시리스트에 목록을 조회한다
- [ ] 내 위시리스트에 상품을 삭제한다


## 구현 전략
- 비밀번호는 Argon2로 해싱해 저장한다 (PasswordEncoder.matches로 검증)
- JWT는 jjwt 라이브러리를 쓴다. JWT에서 payload의 claim은 sub(회원id), exp(제한시간)만 넣는다. iss, aud는 넣지 않는다. (이 과제에서는 발급, 검증하는 서버가 똑같기 때문 - ref: https://www.rfc-editor.org/info/rfc7519/#section-4.1)
- 토큰 검증은 인터셉터(`/api/wishes/**`)에서 헤더 -> 파싱 -> 서명 -> 만료 순서로 한다
  - 이유: @ControllerAdvice로 오류 응답을 통일하기 위해서
- ArgumentResolver가 회원을 조회해 Member로 넘긴다
  - 이유: 요청당 DB 조회를 한 번으로 줄이기 위해서
