# spring-shopping-precourse

온라인 쇼핑몰을 위한 간단한 HTTP API.
요청과 응답은 JSON 형식으로 주고받으며, 스프링 프레임워크 기반 웹 애플리케이션으로 구현한다.

## 구현할 기능 목록

### 1. 회원

- [x] 이메일과 비밀번호로 회원 가입한다.
  - [x] 가입에 성공하면 인증 토큰을 발급한다.
  - [x] 이미 가입된 이메일이면 예외가 발생한다.
  - [x] 이메일 형식이 올바르지 않으면 예외가 발생한다.
  - [x] 이메일 또는 비밀번호가 비어 있으면 예외가 발생한다.
- [x] 이메일과 비밀번호로 로그인한다.
  - [x] 이메일과 비밀번호가 일치하면 인증 토큰을 발급한다.
  - [x] 존재하지 않는 이메일이면 예외가 발생한다.
  - [x] 비밀번호가 일치하지 않으면 예외가 발생한다.
- [x] 인증 토큰을 생성하고 검증한다. (방식은 자유 JWT)
  - [x] 토큰에서 회원 정보를 꺼낸다.
  - [x] 토큰이 없거나 유효하지 않으면 예외가 발생한다.

### 2. 상품

- [x] 상품은 이름, 가격, 이미지 URL로 구성된다.
  - [x] 이미지는 파일 업로드가 아닌 URL 입력 방식으로 관리한다.
- [x] 상품을 생성한다.
- [x] 특정 상품을 조회한다.
  - [x] 존재하지 않는 상품이면 예외가 발생한다.
- [x] 모든 상품 목록을 조회한다.
- [x] 기존 상품의 정보를 수정한다.
  - [x] 존재하지 않는 상품이면 예외가 발생한다.
- [x] 특정 상품을 삭제한다.
  - [x] 존재하지 않는 상품이면 예외가 발생한다.

### 3. 상품 유효성 검사 (생성·수정 시)

- [x] 상품 이름은 공백을 포함하여 최대 15자까지 입력할 수 있다.
  - [x] 15자를 초과하면 예외가 발생한다.
  - [x] 이름이 비어 있으면 예외가 발생한다.
- [x] 상품 이름에는 허용된 특수 문자만 사용할 수 있다.
  - 허용: `(` `)` `[` `]` `+` `-` `&` `/` `_`
  - [x] 그 외 특수 문자가 포함되면 예외가 발생한다.
- [x] 상품 이름에는 비속어가 포함될 수 없다.
  - [x] PurgoMalum API를 호출하여 비속어 포함 여부를 검사한다.
  - [x] 비속어가 포함되어 있으면 예외가 발생한다.
- [x] 가격이 비어 있거나 음수이면 예외가 발생한다.
- [x] 이미지 URL이 비어 있으면 예외가 발생한다.

### 4. 위시 리스트 (인증된 회원만 사용 가능)

- [x] 위시 리스트에 상품을 추가한다.
  - [x] 존재하지 않는 상품이면 예외가 발생한다.
  - [x] 이미 위시 리스트에 있는 상품이면 예외가 발생한다.
- [x] 위시 리스트에 등록된 상품 목록을 조회한다.
- [x] 위시 리스트에서 상품을 삭제한다.
  - [x] 존재하지 않는 위시이면 예외가 발생한다.
  - [x] 다른 회원의 위시이면 예외가 발생한다.
- [x] 인증 토큰이 없거나 유효하지 않으면 예외가 발생한다.

### 5. 예외 처리

- [x] 잘못된 요청에 대해 적절한 HTTP 상태 코드와 오류 메시지를 JSON으로 반환한다.
  - `400 Bad Request` : 유효성 검사 실패
  - `401 Unauthorized` : 인증 실패 (토큰 없음/무효, 로그인 정보 불일치)
  - `403 Forbidden` : 다른 회원의 리소스 접근
  - `404 Not Found` : 존재하지 않는 리소스
  - `409 Conflict` : 중복 데이터 (이메일, 위시 상품)

## API 명세

### 회원

| Method | URL                     | 설명                              |
|--------|-------------------------|-----------------------------------|
| POST   | `/api/members/register` | 회원 가입. 새 회원을 등록하고 토큰을 받는다. |
| POST   | `/api/members/login`    | 로그인. 회원을 인증하고 토큰을 받는다.      |

### 상품

| Method | URL                         | 설명                          |
|--------|-----------------------------|-------------------------------|
| POST   | `/api/products`             | 상품 생성. 새 상품을 등록한다.         |
| GET    | `/api/products/{productId}` | 상품 조회. 특정 상품의 정보를 조회한다.    |
| PUT    | `/api/products/{productId}` | 상품 수정. 기존 상품의 정보를 수정한다.    |
| DELETE | `/api/products/{productId}` | 상품 삭제. 특정 상품을 삭제한다.        |
| GET    | `/api/products`             | 상품 목록 조회. 모든 상품의 목록을 조회한다. |

### 위시 리스트

| Method | URL                    | 설명                                 |
|--------|------------------------|--------------------------------------|
| POST   | `/api/wishes`          | 위시 리스트 상품 추가. 회원의 위시 리스트에 상품을 추가한다. |
| DELETE | `/api/wishes/{wishId}` | 위시 리스트 상품 삭제. 회원의 위시 리스트에서 상품을 삭제한다. |
| GET    | `/api/wishes`          | 위시 리스트 상품 조회. 회원의 위시 리스트에 있는 상품을 조회한다. |

## 프로그래밍 요구 사항

- Google Java Style Guide를 따르되, 들여쓰기는 4 spaces로 한다.
- 들여쓰기 depth는 2까지만 허용한다.
- 메서드 길이는 15줄을 넘지 않으며, 한 가지 일만 하도록 작성한다.
- `else`, `switch`, 3항 연산자를 사용하지 않는다.
- 기능 목록이 정상 동작하는지 JUnit 5와 AssertJ로 테스트한다.
